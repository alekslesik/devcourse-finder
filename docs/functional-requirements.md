# Поисковик обучения разработчиков — требования MVP

Версия: 1.0. Дата: 27.09.2026. Статус: рабочая спецификация для проектирования и реализации.

## 1. Назначение

Пользователь выбирает язык программирования, текущий опыт, цель и бюджет, получает подходящие программы, сравнивает их и переходит на сайт школы. Сервис агрегирует предложения и помогает сделать выбор. Обучение, договор и оплата происходят у поставщика.

Основной сценарий: **условия → выдача → подробности или сравнение → переход к поставщику**.

Обязательные ограничения пользователя: backend на Go, Docker; предпочтение PostgreSQL. Для посетителей не нужны регистрация и оплата.

Принятые проектные решения: Next.js + TypeScript, PostgreSQL, русскоязычный интерфейс, цены в рублях, онлайн-обучение для взрослых. Дополнительные фильтры, сравнение, правила актуальности и импорт ниже — предложенный объём первой версии; документ не означает, что сайт уже реализован.

## 2. Границы первой версии

### Включено

- Go, Python, Java, JavaScript; TypeScript как технология внутри JS-направления.
- Бесплатные и платные курсы, самостоятельные материалы, обучение с наставником.
- Основы языка, первая профессия, смена языка и повышение квалификации.
- Поиск по параметрам, карточка программы, сравнение до трёх предложений, ссылка на подбор.
- Прямые и партнёрские переходы на сайты поставщиков.
- Проверяемый импорт и обновление каталога оператором.
- Минимальная статистика использования поиска и исходящих переходов.

### Отложено

- Пользовательские аккаунты, платежи, корзина, заявки в школы и сбор контактов.
- Отзывы пользователей, рейтинги школ, избранное между устройствами, чат и AI-консультант.
- Кабинет школы, веб-админка, автоматический сбор цен и интеграции с партнёрскими API.
- Поиск по произвольному тексту, Elasticsearch, платное продвижение в выдаче.
- Детские курсы, высшее образование, QA, чистые Data Science/аналитика и DevOps.
- Курсы в иных валютах и автоматическая конвертация цен.

## 3. Роли

| Роль | Возможности |
|---|---|
| Посетитель | Подбор, просмотр, сравнение, копирование ссылки, переход к школе без входа |
| Оператор каталога | Подготовка данных, проверка источников, импорт, публикация и снятие предложений через служебную CLI-команду |

Оператор работает через доступ к серверу/контейнеру; служебные операции не доступны через публичный API. Отсутствие пользовательской регистрации не означает публичное редактирование каталога.

## 4. Структура страниц

| Путь | Назначение |
|---|---|
| `/` | Короткая форма подбора; ниже — опубликованные программы без персональной рекомендации |
| `/courses?...` | Выдача, активные фильтры, сортировка и пагинация |
| `/courses/{slug}` | Программа, доступные тарифы и условия |
| `/compare?offers=...` | Сравнение конкретных предложений |
| `/about` | Как работает подбор, источники, партнёрская модель и границы проверки |

Первый экран позволяет начать подбор. Полноэкранный рекламный блок или обязательная анкета перед фильтрами не нужны. Интерфейс работает на телефоне и компьютере.

## 5. Функциональные требования

### FR-01. Основные параметры

Все поля необязательны. «Неважно»/«Ещё не выбрал» означает отсутствие ограничения.

| Поле | Значения и поведение |
|---|---|
| Язык | Один из Go / Python / Java / JavaScript либо все |
| Опыт | Нет опыта; знаю основы выбранного языка; делаю проекты на выбранном языке; работаю на выбранном языке; программирую на другом языке |
| Другой язык | Необязательное уточнение для последнего варианта; информационный контекст, не жёсткий фильтр MVP |
| Цель | Попробовать; первая профессия; перейти с другого языка; углубить знания; не определился |
| Бюджет | Любой; только бесплатно; платные в диапазоне полной стоимости в рублях |

Если язык ещё не выбран, поле опыта содержит только «нет опыта» и «есть опыт программирования»: подробные уровни доступны после выбора языка. При смене языка зависимый опыт и направление сбрасываются с видимым уведомлением. Бюджет и остальные независимые условия сохраняются.

В бюджетном диапазоне можно задать одну или обе границы; границы включаются. Отрицательные суммы и нижняя граница выше верхней дают ошибку до отправки запроса. При желании включить бесплатные варианты вместе с платным диапазоном есть отдельный переключатель.

### FR-02. Дополнительные фильтры

Открываются по кнопке «Дополнительные условия».

| Поле | Значения |
|---|---|
| Направление | Основы языка; backend; frontend; fullstack; автоматизация |
| Нагрузка | Максимальное число часов в неделю: 5 / 10 / 20 / без ограничения |
| Поддержка | Неважно; самостоятельное обучение; с проверкой кода человеком; с индивидуальными занятиями |
| Расписание | Неважно; свободный график; занятия по расписанию |
| Набор | По умолчанию доступен сейчас; дополнительно разрешить закрытые наборы и предложения с неизвестной доступностью |

Frontend доступен для JS; fullstack — для JS и Python; автоматизация — для Python и Go; основы/backend — для всех четырёх. Перечень — справочник продукта и может расширяться без изменения алгоритма.

У поддержки независимые признаки: проверка кода и индивидуальные занятия не считаются автоматически взаимозаменяемыми. Самостоятельный формат не подразумевает наличие персональной помощи. Неизвестная нагрузка или поддержка не проходит соответствующее жёсткое ограничение.

### FR-03. Запуск поиска и состояние

- Поиск запускается кнопкой «Показать варианты» или Enter. Изменение формы само по себе не запускает запрос.
- После отправки форма и результаты соответствуют одному набору параметров; во время загрузки показано состояние ожидания.
- Результат более старого запроса не заменяет результат более нового.
- Активные фильтры представлены понятными метками. Можно удалить отдельную метку или сбросить всё; эти действия сразу выполняют поиск.
- Применение фильтров и смена сортировки возвращают на первую страницу.
- Все применённые параметры, сортировка и номер страницы записываются в URL. Назад/вперёд и перезагрузка восстанавливают выдачу.
- «Скопировать ссылку» копирует URL; при недоступности буфера показывает поле для ручного копирования.
- Передача ссылки восстанавливает условия, но не гарантирует прежние результаты: каталог мог измениться.

### FR-04. Правила соответствия

Поиск исполняется в Go. Frontend не реализует второй независимый алгоритм подбора.

1. Публикация и доступность проверяются первыми.
2. Язык, направление, бюджет, нагрузка, поддержка и расписание — жёсткие фильтры, когда заданы.
3. Для опыта оператор задаёт допустимые профили аудитории программы. Совпадение проверяется по этому списку, а не по сравнению условных чисел junior/middle/senior. Общий профиль «есть опыт программирования» без выбора языка допускает программы для любого профиля с опытом; результат не обещает достаточную подготовку к конкретному языку и показывает prerequisites. Неизвестная требуемая подготовка при выбранном опыте не проходит фильтр.
4. Для цели оператор задаёт явный список подходящих целей. Выбранная цель должна присутствовать в нём.
5. Неизвестное значение не считается совпадением. При незаданном фильтре оно допустимо и обозначается в карточке. Для ограничения нагрузки верхняя граница заявленного диапазона часов должна быть не выше выбранного максимума.
6. Все ограничения должны выполняться **одним и тем же предложением/тарифом**. Нельзя взять цену дешёвого тарифа, а проверку кода — дорогого.
7. Партнёрская комиссия, наличие договора со школой и клики не влияют на отбор и порядок.

Пример: бюджет до 30 000 ₽ и проверка кода. У курса есть самостоятельный тариф за 20 000 ₽ и тариф с ревью за 40 000 ₽. Курс не проходит поиск.

### FR-05. Выдача и порядок

- Одна карточка на программу; в ней выбран самый дешёвый подходящий тариф с подтверждённой полной ценой. Если таких цен нет и бюджет не задан — первый подходящий тариф по стабильному ID с подписью «Цена не подтверждена».
- Если подходят бесплатный и платный тарифы одной программы, выбирается бесплатный полный вариант; бесплатное демо тарифом полного курса не считается.
- Указано количество найденных программ, а не тарифов. На странице — 12 карточек.
- Порядок по умолчанию называется «По актуальности данных»: сначала актуальные записи, затем требующие обновления; внутри — дата проверки по убыванию, затем стабильный ID.
- Поскольку заданные условия уже выполнены всеми результатами, в MVP не рассчитывается непрозрачный процент соответствия и не используется надпись «лучший курс».
- Дополнительная сортировка: полная цена по возрастанию/убыванию и длительность по возрастанию. Неизвестные значения всегда в конце; одинаковые — по стабильному ID.
- Длительность для сортировки нормализуется в недели; сроки «в своём темпе» без оценки считаются неизвестными. Если указан диапазон, используется верхняя граница, и правило раскрывается в интерфейсе.
- Карточка показывает выбранный тариф; другие тарифы доступны на странице программы.

Изменение относительно ранней идеи: вместо сортировки «по соответствию» без определённой формулы принята проверяемая фильтрация и сортировка по актуальности. Это проектное решение для MVP.

### FR-06. Карточка результата

Обязательные поля: название, поставщик, язык/направление, выбранный тариф, подходящая аудитория, формат, полная цена или явное отсутствие цены, длительность, нагрузка, поддержка, доступность, дата проверки.

Показывать до трёх объяснений из фактических совпадений, например «Для перехода с другого языка», «До 10 часов в неделю», «Есть проверка кода». Объяснения строятся из тех же данных, по которым прошла фильтрация. Неподтверждённое не превращается в преимущество.

Действия: «Подробнее», «Сравнить», «На сайт курса». Для закрытого/неизвестного набора последнее действие называется «Проверить набор». Вся карточка не должна быть единой внешней ссылкой: действия доступны отдельно с клавиатуры.

### FR-07. Страница программы

Показывает:

- Кому подходит и какие знания требуются.
- Цель, содержание и технологии, самостоятельную практику и проекты.
- Как проверяют задания, какая помощь включена, ограничения выбранного тарифа.
- Расписание, длительность, нагрузку, срок доступа и состояние набора.
- Тарифы с отдельными ценами и поддержкой; отсутствующие сведения явно отмечены.
- Источники, дату проверки цены и остальных условий, характер проверки: опубликованная программа / просмотренное демо.
- Прямое пояснение партнёрского перехода, если он используется.

Непроверенные утверждения о зарплате, гарантированном трудоустройстве и качестве не добавляются от имени сервиса. На старте нет общего числового рейтинга школ.

### FR-08. Цена и бесплатность

- Стоимость хранится целым числом копеек; валюта MVP — RUB.
- Типы цены: точная полная; «от»; неизвестна. Признак бесплатности хранится отдельно и требует подтверждения полного заявленного объёма.
- Строгий бюджетный фильтр использует только актуальную точную полную цену. Цена «от» и неизвестная цена не проходят ограниченный бюджет.
- Цена рассрочки показывается отдельно только при наличии числа платежей и общей суммы; не участвует в фильтре полной стоимости.
- Полная бесплатная программа может иметь отдельную платную услугу сертификата: это раскрывается и не маскируется.
- Бесплатный вводный модуль/демо платной программы не делает её бесплатной. Самостоятельная вводная программа допустима как отдельная запись с собственным объёмом и целью «попробовать».
- Цена считается неподтверждённой после 30 дней без проверки либо после окончания акции — что наступит раньше. Порог настраивается; дата истечения без времени трактуется как конец дня Europe/Moscow.
- Истёкшая акция заменяется актуальной подтверждённой базовой ценой; если её нет, отображается «Цена требует уточнения». Старая сумма не участвует в сортировке как действующая.
- Все правила актуальности применяются при чтении данных, даже если фоновая задача не запускалась.

### FR-09. Сравнение

- До трёх предложений (программа + тариф); выбор из карточек и страницы курса.
- Повторное добавление той же записи не создаёт дубль. Четвёртая запись не заменяет существующие: посетитель видит предложение удалить одну.
- Разрешено сравнить два тарифа одной программы, если посетитель выбирает их явно.
- Поля: аудитория, цель, содержание, полная цена, длительность, нагрузка, расписание, поддержка, практика, доступность, дата проверки, ссылка на поставщика.
- Неизвестные значения отображаются одинаково — «Не указано»/«Не подтверждено» в зависимости от причины.
- Выбор сохраняется в localStorage этого браузера; если оно недоступно — в памяти текущей вкладки. Аккаунт не нужен.
- URL сравнения имеет приоритет над локальным выбором и воспроизводит список в том же порядке. Удалённые/снятые позиции обозначаются как недоступные и могут быть удалены пользователем.
- При одной позиции разрешён просмотр, при нуле — предложение вернуться к каталогу.

### FR-10. Внешний переход

- Backend определяет адрес по ID предложения; произвольный URL из запроса не принимается.
- Используется активная подтверждённая партнёрская ссылка, иначе официальный адрес программы.
- Разрешены только HTTPS-адреса утверждённых оператором доменов школ и партнёрских сетей. Служебные, локальные адреса и исполняемые URL-схемы запрещены.
- Переход не требует email, телефона или регистрации и не отправляет выбранный профиль посетителя школе.
- Ссылка открывается в новой вкладке с безопасными атрибутами. Партнёрские ссылки помечаются `sponsored`.
- При отказе аналитики переход продолжается. Недоступный/неизвестный ID даёт понятную страницу ошибки без перенаправления.
- Переход фиксируется как клик, а не покупка. Наличие программы не считается фактом начисления комиссии.

### FR-11. Пустые результаты и ошибки

- При нуле результатов видны применённые условия и действия «Изменить фильтры»/«Сбросить». Условия не ослабляются автоматически.
- Можно предложить явно убрать одно ограничение, но нельзя заявлять, что результаты появятся, без проверочного запроса.
- При ошибке сервера сохраняется форма и доступна повторная попытка; сообщение не имитирует отсутствие курсов.
- Неизвестные URL-параметры игнорируются; известные с недопустимыми значениями дают сообщение о некорректной ссылке и возможность сброса. API возвращает 400 с указанием поля.
- Несуществующая программа — 404. Снятая программа по старому адресу показывает архивный статус и ссылку на поиск, без активного предложения купить.
- Пустая БД показывает честное сообщение «Каталог пока не заполнен».

### FR-12. Управление каталогом

Для MVP — JSON-файл и служебная Go CLI-команда в backend-контейнере.

1. Оператор готовит данные по документированной схеме.
2. Команда `catalog validate` проверяет файл без изменений в БД и выводит ошибки по записям/полям.
3. `catalog import --dry-run` показывает добавления, изменения и снятие с публикации.
4. `catalog import` применяет весь файл транзакционно: ошибка не оставляет частичный импорт.
5. Повторный импорт с теми же стабильными ID не создаёт дубли. Отсутствующая в файле запись не удаляется автоматически; снятие задаётся явно.
6. Изменения записываются в журнал импорта: время, оператор, идентификатор партии и изменённые поля. Предыдущая редакция позволяет восстановить данные повторным импортом.
7. Публикация требует источника, даты проверки, названия, поставщика, языка, типа программы, профилей опыта, целей, статуса набора и официальной ссылки. Неизвестные цена/нагрузка допустимы как неизвестные.
8. Изменения доступны посетителям не позднее чем через 60 секунд после успешного импорта; API и frontend не продолжают показывать устаревший кэш дольше этого срока.

Статусы публикации: draft / published / archived. Статусы набора: open / continuous / closed / unknown. Это независимые признаки. Для open хранится дата окончания набора, если известна; после неё статус для поиска становится unknown до проверки. continuous означает постоянный доступ, а не постоянное наличие акции.

Прочие условия программы после 90 дней без проверки помечаются устаревшими, но автоматически не удаляются. Поиск учитывает известные условия с видимой оговоркой; цена подчиняется более строгому FR-08. CLI выдаёт список записей для обновления.

### FR-13. Аналитика проверки спроса

События: применённый поиск, нулевая выдача, просмотр программы, открытие сравнения, запрос внешнего перехода. Поля ограничены справочными значениями, ID, временем и случайным ID события. Email, телефон, полные IP, fingerprint и произвольные URL не входят в полезную нагрузку.

Дедупликация по ID события; повторные запросы редиректа могут оставаться повторными кликами и не называются уникальными посетителями. Служебные запросы/известные боты исключаются из отчётов насколько возможно; точность человеческих визитов не гарантируется.

Сырые события хранятся 30 дней с ежедневной очисткой; агрегаты по дням — до 12 месяцев. Ретенция инфраструктурных логов задаётся отдельно. Аналитика не блокирует поиск и переходы. Оператор получает отчёт CLI: частота фильтров, доля нулевой выдачи, просмотры и клики по программам. Отдельный dashboard не требуется.

Отношение кликов к просмотрам — показатель событий, не конверсия в покупку. Условия статистики описываются на `/about`; для будущих сторонних счётчиков требования рассматриваются отдельно.

## 6. Данные

| Сущность | Основные данные |
|---|---|
| Provider | ID, название, официальный домен, описание |
| Course | ID, slug, provider_id, название, тип, языки, направления, аудитория, цели, требования, программа, источники, статус публикации |
| Offer | ID, course_id, название тарифа, точная цена/тип цены, RUB, бесплатность, поддержка, формат, расписание, нагрузка, длительность, доступ, статус и даты набора |
| Price evidence | Цена базовая/акционная, источник, checked_at, valid_until, условия акции; предыдущие значения |
| Outbound link | offer_id, официальный URL, партнёрский URL и статус его проверки, разрешённые домены |
| Import revision | Партия, оператор, время и предыдущие/новые значения |
| Event / Daily aggregate | Разрешённые поля событий и агрегированная статистика |

У условий, отличающихся между тарифами, источник истины — Offer. Общие описания курса не могут переопределить тариф при фильтрации. Неизвестные значения — NULL/явный статус, а не ноль. Цена 0 разрешена только для подтверждённого бесплатного предложения.

Основные фильтруемые поля и связи — обычные таблицы PostgreSQL. JSONB применяется для дополнительных исходных сведений и журнала изменений, не вместо всей схемы. Время хранится в UTC; отображение расписания содержит часовой пояс.

Исследовательский файл `research/providers-2026-09-27.json` описывает площадки, а не готовые предложения. Его нельзя напрямую публиковать как покурсовый каталог: требуется дополнить программы, тарифы, источники и условия.

## 7. Технологический стек и границы компонентов

| Часть | Выбор | Основание проектного решения |
|---|---|---|
| Frontend | Next.js, React, TypeScript; CSS Modules | Серверное представление страниц каталога и интерактивные фильтры в одном проекте |
| Backend | Go, `net/http`, REST/JSON | Единый поиск, правила цен, импорт и исходящие переходы |
| БД | PostgreSQL, SQL-миграции | Связанные программы/тарифы, фильтрация, транзакции импорта |
| Доступ к БД | pgx, явные параметризованные SQL-запросы | Контролируемые запросы без обязательного ORM |
| Окружение | Dockerfiles + Docker Compose | Воспроизводимый запуск frontend, API и БД |
| Контракт | OpenAPI; типы frontend из контракта | Согласованные фильтры, ответы и ошибки |

Next.js отвечает за представление; не подключается напрямую к БД и не дублирует бизнес-логику Go. Redis, очереди, микросервисы и поисковый кластер для MVP не нужны. Версии зависимостей и образов фиксируются при реализации после проверки совместимости; теги `latest` не используются.

Схема: браузер → Next.js / публичный Go API → PostgreSQL. SSR Next.js обращается к Go по внутренней сети. `/api/*` и `/out/*` доступны браузеру через единый origin; конкретная настройка reverse proxy определяется развёртыванием.

Основания выбора: [Next.js — серверные и клиентские компоненты](https://nextjs.org/docs/app/getting-started/server-and-client-components), [PostgreSQL — JSONB](https://www.postgresql.org/docs/current/datatype-json.html), [Docker Compose — модель приложения](https://docs.docker.com/compose/intro/compose-application-model/). Выбор стека — решение проекта, а не утверждение, что альтернативы не подходят.

## 8. Публичный API — предварительные границы

| Метод и путь | Назначение |
|---|---|
| GET `/api/v1/catalog/options` | Справочники фильтров и допустимые сочетания |
| GET `/api/v1/courses` | Фильтры, сортировка, page/page_size; программы с выбранным подходящим offer |
| GET `/api/v1/courses/{slug}` | Программа и опубликованные предложения |
| GET `/api/v1/compare?offer_ids=...` | От 1 до 3 уникальных предложений; статусы недоступных ID |
| POST `/api/v1/events` | Ограниченный набор событий с валидацией и rate limit |
| GET `/out/{offer_id}` | 302 на проверенный адрес, `Cache-Control: no-store` |
| GET `/health/live`, `/health/ready` | Состояние процесса и готовность обслуживать запросы |

Ответ поиска: items, total (программы), page, page_size, applied_filters, data_as_of. В items — выбранный offer, объяснения и предупреждения об актуальности. page_size по умолчанию 12, максимум 48. Страница за пределами выдачи возвращает пустой items с правильным total; UI предлагает первую страницу.

API возвращает структурированную ошибку с кодом, безопасным сообщением и полями валидации; внутренние SQL, стеки и секреты не раскрывает. Контракт уточняется перед реализацией и не меняет правила соответствия из раздела 5.

## 9. Нефункциональные требования

- **Доступность:** основные сценарии с клавиатуры; связанные подписи полей, видимый фокус, ошибки текстом; цвет не единственный носитель смысла. Ориентир — WCAG 2.2 AA для реализуемых компонентов.
- **Адаптивность:** ширина от 360 px; основной экран и карточки без горизонтального скролла. Сравнение на мобильном допускает явно обозначенную прокрутку таблицы.
- **Производительность:** целевой p95 ответа поиска ≤500 мс при 10 000 опубликованных предложений и 20 параллельных запросах на стенде 2 vCPU/4 GB, без учёта внешней сети. Методика: фиксированные данные и смесь фильтров, прогрев 1 мин., замер 5 мин. Это цель приёмки, не измеренный результат.
- **SEO:** серверный HTML страниц программ, title/description, sitemap опубликованных программ. Параметризованная выдача и сравнение — noindex, follow. Архивные страницы исключаются из sitemap.
- **Безопасность:** параметризованный SQL, проверка входных данных и ограничение запросов; внешние URL только из каталога; секреты вне репозитория. БД не доступна из интернета.
- **Наблюдаемость:** структурированные логи с request_id без секретов, health checks, журнал неуспешных импортов.
- **Восстановление:** ежедневная резервная копия БД, хранение 7 дней; перед публичным запуском проверено восстановление на отдельной БД. Это эксплуатационная задача, не пользовательская функция.

### Docker

- Compose содержит `frontend`, `api`, `db` и одноразовый сервис миграций; служебная CLI использует образ `api`.
- Запуск приложения документирован одной основной командой `docker compose up --build`; миграции завершаются до готовности API.
- PostgreSQL использует постоянный volume; обычный restart/down без удаления volumes сохраняет каталог.
- `.env.example` содержит описание переменных без рабочих секретов. Production требует заданных секретов, а не общедоступных значений по умолчанию.
- В production опубликован только входной HTTP(S)-сервис; TLS и домен настраиваются при выборе хостинга.
- Демоданные отделены от production-каталога и не загружаются автоматически при перезапуске.

## 10. Критерии приёмки

| ID | Проверка | Ожидаемый результат |
|---|---|---|
| AC-01 | Посетитель открывает главную | Форма доступна сразу, вход и контакты не запрашиваются |
| AC-02 | Go + переход с языка + до 30 000 ₽ | Все результаты соответствуют одному тарифу по всем заданным условиям |
| AC-03 | Тариф 20 000 ₽ без ревью и 40 000 ₽ с ревью; бюджет 30 000 ₽ + ревью | Программа исключена |
| AC-04 | Полная цена неизвестна либо «от 20 000 ₽», бюджет ограничен | Предложение исключено; при любом бюджете допускается с оговоркой |
| AC-05 | «Только бесплатно» | Нет платных курсов, замаскированных бесплатным вводным модулем |
| AC-06 | Акция истекла либо цена не проверялась более 30 дней | Сумма не считается действующей; используется актуальная база или неизвестная цена |
| AC-07 | Опыт не подходит prerequisites | Курс не проходит поиск, даже если язык и цена совпадают |
| AC-08 | Нет подходящих программ / сервер недоступен | Разные состояния; форма сохраняется, ограничения не меняются |
| AC-09 | Копирование URL и открытие в другом браузере | Восстановлены фильтры, сортировка и страница; результаты взяты из текущей БД |
| AC-10 | Добавление 4-го предложения в сравнение | Первые три сохранены, показано ограничение |
| AC-11 | Переход по URL сравнения | Восстановлены нужные тарифы; снятые позиции обозначены |
| AC-12 | Переход к школе при отказе записи аналитики | Переход выполнен; произвольный адрес через параметры не принимается |
| AC-13 | Партнёрская ссылка отсутствует | Используется официальный адрес; порядок выдачи не меняется |
| AC-14 | Повторный валидный импорт / импорт с ошибкой | Нет дублей / нет частично применённых данных |
| AC-15 | После импорта изменена цена | Новая цена и результат фильтра видны не позднее 60 секунд |
| AC-16 | Набор закрыт | По умолчанию исключён; с явным разрешением показан с правильным статусом |
| AC-17 | Быстро отправлены два разных поиска | Поздний ответ первого не заменяет второй |
| AC-18 | Перезапуск Compose | Каталог сохранён; миграции повторно безопасны |
| AC-19 | Проверка на 360 px и с клавиатуры | Основной сценарий выполнен, управление доступно |
| AC-20 | Поиск по зафиксированному нагрузочному сценарию | Выполнена цель p95 или задокументирована причина до выпуска |

**Приёмка AC-02—AC-07 (04.10.2026):** Все шесть критериев проверены через настоящий production HTTP-handler с PostgreSQL, валидированным импортом и кэшем. В браузере проверены перевод рублей в копейки и оговорки неподтверждённых цен. Результаты и оставшиеся критерии — в [таблице готовности](mvp-readiness.md); блок ожидает слияния.

При реализации автоматизировать прежде всего правила фильтрации/цен, выбор тарифа, импорт и основной браузерный сценарий. Для документа тесты приложения ещё не выполняются.

## 11. Готовность к первому публичному запуску

Предлагаемый минимум данных: 20 проверенных программ, по 5 на язык. В каждом направлении — хотя бы одна бесплатная и одна платная программа; во всём каталоге представлены и новичковый, и опытный профили. Это требование к наполнению, а не показатель размера рынка.

Для каждой опубликованной записи проверены источник, текущий тариф, наличие перехода и статус набора. Если точную цену установить нельзя, она остаётся неизвестной, а не копируется из устаревшего обзора. Наличие партнёрского договора не является условием публикации.

Результат этапа требований: определены поведение сайта, правила данных, стек и критерии приёмки. Следующий этап реализации — схема БД и OpenAPI на основе этой спецификации, затем поиск, карточки, сравнение и импорт.
