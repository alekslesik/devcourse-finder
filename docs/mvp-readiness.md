## Статус каждого пункта ТЗ

**Проверено локально** — требуемая реализация есть и относящиеся к ней локальные проверки прошли. **Частично** — остаются требования или существенные проверки. **Не выполнено** — результата по требованию пока нет.

Отдельно: **принят по ТЗ** пункт будет только после слияния, зелёного CI и фиксации необходимой приёмки. Для новых рабочих изменений этот этап ещё не пройден. Локальный статус не означает готовность production.

## Проверка критериев приёмки

Тесты правил AC-02—AC-07: [pricing_acceptance_test.go](../backend/pricing_acceptance_test.go). Браузерные проверки: [pricing.spec.ts](../frontend/tests/pricing.spec.ts).

| ID | Статус | Результат / основание |
|---|---|---|
| AC-02 | Проверено, слито | HTTP + PostgreSQL: Go, профиль/цель switch и бюджет ≤30 000 ₽; контроль языка, аудитории, цели и превышения на 1 копейку, включённая граница бюджета. Chromium: 30 000 ₽ отправляются как 3 000 000 коп., форма и URL сохранены. TestAcceptanceAC02GoSwitchBudget, pricing.spec.ts |
| AC-03 | Проверено, слито | HTTP + PostgreSQL: 20 000 ₽ без ревью + 40 000 ₽ с ревью не проходят бюджет 30 000 ₽ с ревью; при бюджете 40 000 ₽ выбран настоящий тариф с ревью. Положительные контроли для бюджета и поддержки. TestAcceptanceAC03OneTariffMustMeetBudgetAndReview |
| AC-04 | Проверено, слито | HTTP + PostgreSQL: неизвестная цена и «от» исключаются при min/max, допускаются без лимита с effective_price=null и сортируются после подтверждённых цен. Chromium: явные оговорки вместо точной суммы. TestAcceptanceAC04UnconfirmedPrices, pricing.spec.ts |
| AC-05 | Проверено, слито | HTTP + PostgreSQL: только подтверждённая нулевая цена полного курса проходит budget=free; платная программа с бесплатным вводным уроком и устаревшая бесплатность исключены. Проверены платный фильтр и явное include_free. TestAcceptanceAC05FreeMeansFullCourse |
| AC-06 | Проверено, слито | HTTP + PostgreSQL: истёкшая/старше 30 дней цена не проходит бюджет и не сортируется как действующая; выбирается актуальный базовый тариф либо effective_price=null. Истечение проверено на уже прогретом кэше без импорта/фоновой задачи. Chromium: старая сумма не отображается как действующая. TestAcceptanceAC06*, pricing.spec.ts |
| AC-07 | Проверено, слито | HTTP + PostgreSQL: каждый из none/basics/projects/working/switch проверяется по явному списку аудитории, без шкалы seniority. Проверены несколько допустимых профилей и общий experienced; старая запись с неизвестными prerequisites исключается при выбранном опыте, допускается без него. TestAcceptanceAC07* |
| AC-01 | Проверено локально, ожидает слияния | Chromium: анонимная главная показывает доступную форму ещё до ответа API и при 503; отсутствуют обязательные поля входа, email/телефона и модальный барьер. acceptance.spec.ts |
| AC-08 | Проверено локально, ожидает слияния | Chromium: пустая выдача, 503 и повтор различаются; язык, опыт, цель, обе границы бюджета, ревью, расписание, часы, набор, сортировка и URL сохраняются без ослабления фильтров. acceptance.spec.ts |
| AC-17 | Проверено, слито | После Go → Python поздние успех, HTTP 503 и ошибка обработки Go не меняют карточки, форму, URL и состояние загрузки/ошибки Python; устаревшее search-событие не отправляется. Все три сценария воспроизводили сбой до исправления и прошли после него с fixture API и настоящим стеком. Тест: [search-race.spec.ts](../frontend/tests/search-race.spec.ts) |

Результаты по каждому критерию дополняются по мере приёмки. Новые изменения ожидают слияния; production-каталог и резервное копирование проверяются отдельно.
